# 持ち場 v1: 地図を 1 枚の HTML に書き出す

## 目的

「AI が作った物を自分や人に説明できない」を解くための、最初の部品。
対象 repo の設計の表・コードのつながり・git の変更から地図を作り、1 枚の HTML に書き出す。
AI は使わない (使える AI は職場ごとに違う。どの AI で開発しても同じ地図になるように)。


## 使い方

```
node src/entry/cli.mjs map <repoの中の対象フォルダ> [--since <日数 or YYYY-MM-DD>] [--arch <md>] [--labels <json>] [--story <json>] [--out <file.html>]
```

- 例: `node src/entry/cli.mjs map C:\work\shop-app --since 7 --labels examples/labels.example.json --out out/shop-app.html`
- `--since` の既定: 対象フォルダの最後の commit の日から 1 日前まで (「最後に動いた日」の変更が光る)
- `--out` の既定: `out/<フォルダ名>-map.html`
- 何も常駐しない。書き出したら終わる。exit 0 = 書けた / 1 = 入力の誤り (直し方を 1 行で出す) / 2 = 予期しない失敗

## 入力 (全部、読むだけ。対象 repo に何も書かない)

1. `<対象>/spec/architecture.md`、または `--arch <file.md>` で渡した対象の外のファイル (対象の repo に表を足せない時。表の中のパスは対象フォルダからの相対のまま)
   - 表 1「役割対応表」: `| 役割 | パス |`。役割は shared / core / adapter / entry。パスは空白区切り
   - 表 2「外部境界表」: 1 列目に adapter のファイル (バッククォートや「→」を含む行もある。最初に出る `*.mjs` / `*.js` / `*.html` のパスを取る)、2 列目が相手 (外の何か)
   - 表が見つからない時は exit 1 と「spec/architecture.md に 役割対応表 が無い」
2. コードのつながり: 表 1 に載ったファイルの中の `import ... from '...'` / `import('...')` / `require('...')` / HTML の `<script src="...">`。相対パスだけを解決し、表 1 にあるファイルどうしの線にする
3. git: `git -C <対象> log --since=<日> --name-only --format=...` で、変わったファイルと commit の題・hash・日時。merge commit の題に `#123` があれば PR 番号として拾う
4. (あれば) `gh pr view <番号> --json title,body,url,statusCheckRollup` で理由と CI の結果。gh が無い・失敗したら黙らず「PR の説明は取れなかった (gh 無し)」と画面に出し、残りは作る (optional + fallback)
5. (あれば) `--labels` の JSON: `{ "groups": { "roster": "名簿", ... }, "outside": { "Claude API": "AI (Claude)" } }`。無ければ英字の名前のまま

## 地図の作り方

- **箱 = 役割 × 機能のまとまり**。ファイル名の最初の語 (`roster-core.js` → `roster`、`reply-page.js` → `reply`、`index.html` → `index`) で同じ役割の中をまとめる。1 つしか無いまとまりも箱にする
- 列は左から entry / adapter / core / shared / 外 (表 2 の相手)。116 ファイルの試し先 (Web アプリ) で箱が 40 前後に収まること
- **線** = まとまりどうしの import の合計 (向きあり、太さは本数)。adapter → 外 は表 2 から
- **光る箱** = 期間内に変わったファイルを含む箱。新しく増えたファイルを含むなら「新」、それ以外は「変更」の札
- 箱を押すと右の欄に: 箱の名前 / 中のファイル (変わった物に印、各行に「開く」) / この期間の commit と PR (題・理由・CI) / つながっている箱 (押すとそこへ飛ぶ) / その箱の線 (使う側と使われる側の 1 段) だけを光らせ、他の線はほぼ消す。マウスを乗せると線を下見できる
- 上の帯「今日見る所」: 光った箱を変更行数の多い順に 3 つまで
- 「開く」= `vscode://file/<絶対パス>` のリンク (VS Code があれば開く)。並べて「場所をコピー」ボタン (絶対パスをクリップボードへ)

## 出力の HTML

- 1 ファイルで完結。外への通信なし、外部ライブラリなし。データは HTML の中の `<script type="application/json">` に入れる (HTML の文字を直接組み立てて入れない。DOM API か textContent で描く)
- 見た目は `mocks/concept-a-map.html` に合わせる (OKLCH の色、BIZ UDPGothic、暗い表示が既定 + 明るさの切替、本文 15px 以上)
- 1520x960 で全体が見え、拡大縮小とドラッグで動かせる

## 構造 (architecture-standard の 4 役割)

| 役割 | パス | 中身 |
|---|---|---|
| shared | src/shared/ | データの形 (Map / Box / Edge / Change) と検査 |
| core | src/core/ | 表を読む・まとめる・線を数える・並べる。外界を import しない (fs / child_process / process.env / 時計 禁止) |
| adapter | src/adapter/ | fs で読む、git と gh を呼ぶ。それぞれ fake を持つ (fake-*.mjs) |
| entry | src/entry/ | cli.mjs (引数・exit code・配線 1 点)、render.mjs (HTML を書き出す。テンプレートは src/entry/template.html) |

- Node 標準だけ (依存 0)。テストは `node --test`。core のテストは fake だけで数秒
- `npm run arch` 相当: `node test/arch.check.mjs` が上の依存方向を検査する (対象 0 件なら失敗 = false-safe)

## 完了の条件

1. `node --test` が全部通る (core の単体、fake の adapter で cli の通し、arch 検査)
2. 本物の試し先 (116 ファイルの Web アプリ) で地図を書き出し、headless Chrome の写真 (暗い・明るい) で、箱が重ならず読め、光る箱を押した状態も確かめた
3. 対象 repo に何も書いていない (対象 repo の `git status --porcelain` が実行前後で同じ)
