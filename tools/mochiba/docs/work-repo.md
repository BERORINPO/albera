# 仕事の repo で使う (repo に何も足さない)

仕事の repo には表を足せないことが多い。その時は表を repo の外に置いて `--arch` で渡す。
地図・紙芝居・練習の HTML は `out/` に書かれ、外へは何も送らない (外への通信なし)。

## 要る物

| 物 | 確かめ方 | 無い時 |
|---|---|---|
| Node 22 以上 | `node -v` | 入れる (Node の標準部品だけで動く。npm install は要らない) |
| git | `git --version` | 入れる (変更を光らせるのに使う) |
| gh (GitHub CLI) | `gh --version` | 無くても動く。PR の説明と CI の結果が出ないだけ |

## 使い方

```
node src/entry/cli.mjs map <repo の中の対象フォルダ> --since 7 --arch out/<名前>-arch.md
```

- 書き出し先は `out/<フォルダ名>-map.html`
- 表の中のパスは、対象フォルダからの相対パスで書く。書き方の見本は [spec/architecture.md](../spec/architecture.md)

### 表を AI に書かせる

仕事で使える AI に、対象フォルダを開いた状態で次を頼む。

1. このフォルダで `mkdir out` (もうあれば要らない)
2. 返ってきた表の部分を新しいファイルに貼り、`out/<名前>-arch.md` として UTF-8 で保存する (仕事の repo には置かない)
3. `--arch out/<名前>-arch.md` を付けて書き出す。「ファイルが 1 つも無い」と出たら、表のパスが対象フォルダからの相対になっているかを見る

```
このフォルダのソースファイル (.js / .mjs / .html) を 4 つの役割に分けた表を、次の形の markdown だけで書いて。
- shared = 型・検査・共通の名前 (何も import しない物)
- core = 計算だけで外と話さない物
- adapter = 外 (DB・API・ファイル・画面の外の仕組み) と話す物
- entry = 起動・画面・入口
パスは対象フォルダからの相対パスで、区切りは / にする (\ は使わない)。フォルダごとでもよい (末尾に /)。説明の文は付けない。

## 1. 役割対応表
| 役割 | パス |
|---|---|
| shared | ... |
| core | ... |
| adapter | ... |
| entry | ... |

## 2. 外部境界表
| adapter | 相手 |
|---|---|
| <adapter のファイル> | <話す相手の名前> |
```

- 紙芝居と練習の問いを普通の言葉にしたい時: 画面の「AI に書かせる文をコピー」→ 仕事で使える AI に貼る → 返ってきた JSON を `out/` に保存 → `--story out/<名前>.json` を足して書き出し直す

## 守ること

- 書き出した HTML には、対象のコードの名前とパスが入る。仕事の外へ持ち出さない
- 直してほしい所や欲しい機能は issue に書く。その時、仕事のコード・名前・地図の写真は貼らず、「何が要るか」だけを書く
