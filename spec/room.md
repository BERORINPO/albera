## 1. What it is

`albera-runtime room` = the wall turned into a canvas. Cameras (live VM screens with the AI cursor) sit on a dotted canvas.
Bero, the main AI, floats over it: it looks around, notices (stall, a DONE claim, a limit), points at a camera, says one line,
draws a figure built from the real log, and opens a decision card. Every hands step and every human choice goes into the ledger.

Same host model as the wall: 127.0.0.1 only, bootstrap code -> HttpOnly cookie, CSP `default-src 'none'` (+ self), no-store,
text only through `textContent` / DOM APIs. New: one write route (`POST api/decide`) that can start or stop hands on a VM, so
it is guarded like `approval-host` (Origin, Sec-Fetch-Site, JSON content type, session cookie, card + choice must be open and unused).

Bero is rule-based in v0.8 (no LLM): words come from dictionaries by code. An LLM wording step can be added later behind the same codes.

## 2. Data flow

```
agent-fleet (hands loops) --onEvent(vmId, ev)--> room-journal.recordFleetEvent  --> ledger entries
                                     \--> agent-status-board (cursor, step, usd, note)
host tick (1 s):  director.tick({now, agents: board.snapshot(), entries: journal.since(cursor)})
                  -> {acts, ledger}  -> host appends RoomEvents (bero / ledger)
UI poll (1 s):    GET api/state?since=N -> {now, staleAfterMs, vms, events, nextSince}
UI:               app.mjs plays bero acts in order (await each), adds ledger rows, cards open via the 'card' act
human choice:     POST api/decide {cardId, choiceId} -> director.decide -> Effect -> host runs it on the fleet
                  -> ledger 'human_choice' + RoomEvent card_closed
```

## 4. Codes and params

Ledger (`LEDGER_CODES`, words: C):

| code | actor | params |
|---|---|---|
| `hands_started` | hands | `task` (cut to 200) |
| `hands_step` | hands | `step`, `usd`, `action` (last action name or ''), `note` (the AI's own text this step, cut to 160) |
| `hands_ended` | hands | `outcome` (HAND_OUTCOMES), `claim` (cut to 200), `steps`, `usd` |
| `hands_stalled` | bero | `seconds` (no action for that long while running) |
| `bero_noticed` | bero | `what` (a CARD_CODES value) |
| `bero_figure` | bero | `kind` (FIGURE_KINDS) |
| `bero_card` | bero | `cardCode` |
| `human_choice` | human | `cardCode`, `choiceCode`, `effect` |
| `start_approved` | bero | none. A card job on this VM was approved (only with a start gate); the job starts next |
| `start_refused` | bero | `code`: a fixed code of task-start-gate.mjs, or the fleet's own (`vm_busy`, `over_budget`, ...). No job was started |

Say (`SAY_CODES`, words: D). Params: `cam` (camera label), `seconds`, `claim`, `usd`, `count`, `steps`.
Card (`CARD_CODES`, words: D). Choice codes are D's own (for example `close_it`, `check_again`, `mark_done`, `stop_it`, `later`).

## 5. Module interfaces (cross-part, fixed)

Server side (Node, `./` imports only, no process execution):

```js
// C: room-journal.mjs
createRoomJournal({ max = 500, now = Date.now }) -> {
  record({ vmId, actor, code, params }) -> LedgerEntry,      // assigns seq and at; params through cleanParams
  recordFleetEvent(vmId, loopEvent) -> LedgerEntry | null,   // 'step' -> hands_step, 'end' -> hands_ended, first step -> hands_started is recorded by the host with the task
  since(seq) -> LedgerEntry[],  all() -> LedgerEntry[],  lastSeq() -> number,
}
// C: room-figures.mjs  (pure)
buildFigure(kind, entries, { vmId = null, figureId, frames = {} }) -> FigureSpec | null
  // frames = { before: frameId|null, after: frameId|null } for 'ba'. Returns null when entries are not enough.

// D: bero-director.mjs  (pure except for the injected clock values it is given)
createBeroDirector({ buildFigure, stallMs = 45_000, patrolMs = 20_000, labelOf = (vmId) => vmId }) -> {
  tick({ now, agents, entries }) -> DirectorOutput,          // agents = agent-status-board snapshot
  decide(cardId, choiceId, now) -> { ok: true, effect: Effect, ledger: [...] } | { ok: false, code: 'card_unknown'|'card_closed'|'choice_unknown' },
  openCards() -> DecisionCard[],
}

// B: agent-fleet.mjs (addition)
fleet.startJob(vmId, task) -> { ok: true } | { ok: false, code: 'vm_busy'|'vm_unknown'|'over_budget'|'fleet_stopped' }
fleet.stopVm(vmId) -> boolean

// B: room-host.mjs
createRoomHost({ vms, driver, board, journal, director, fleet, captureIntervalMs, now }) -> { listen(port) -> {url, bootstrapCode}, close(), tickOnce() }
  // GET  /room/                      UI files (index.html, *.mjs, *.css under room-ui/)
  // POST /room/api/session           bootstrap -> cookie (as the wall)
  // GET  /room/api/state?since=N     {now, staleAfterMs, vms: [wall describe + agent], events: RoomEvent[] (<=200), nextSince}
  // GET  /room/api/vms/<id>/screen.png, /room/api/frames/<frameId>.png   (pinned frames: at most 8, oldest dropped)
  // POST /room/api/decide            {cardId, choiceId} -> runs the Effect: stop -> fleet.stopVm, nudge / recheck -> fleet.startJob
```

## 7. Automatic checks (v0.9)

Why: a DONE claim made the person the checker for every VM. Now ALBERA checks the VM itself and the person is asked only when the check fails or cannot run.

Flow:
```
hands 'end' with claimed_done, and the VM has checks
  -> host records `check_started` {count} BEFORE `hands_ended` (same moment, in this order)
  -> host runs checker.run(vmId, checks) (async, one at a time per VM, 60 s timeout)
  -> host records `check_done` {verdict, checks, failed, detail} (detail: first failing "path: finding", cut to 200)
Director: hands_ended(claimed_done) for a VM with a pending check_started -> no card, say `checking`.
          check_done passed -> say `verified` (no card). failed -> card `check_failed`. unavailable -> card `check_unavailable`.
          A VM without checks keeps today's `claimed_done` card.
```
`recheck` jobs end like any job, so their DONE is checked again.

Ledger params: `check_started` {count}; `check_done` {verdict, checks, failed, detail}. Actor of both: `bero` (Bero had them checked).
Say params: `cam`, `checks`, `failed`, `detail`. Card params: `cam`, `detail`, `claim`.
Choices (D): check_failed -> check_again = recheck, mark_done = accept (the person overrides), later = dismiss;
check_unavailable -> mark_done = accept, check_again = recheck, later = dismiss.

Checker (B):
```js
// fake-guest-checker.mjs
createFakeGuestChecker(script) -> { run(vmId, checks) -> Promise<CheckReport> }      // script: vmId -> CheckReport[] in order
// hyperv-guest-check-prototype.mjs  (same-user prototype, like the desktop broker)
createHyperVGuestChecker({ user = 'Administrator', passwordFile }) -> { run(vmId, checks) -> Promise<CheckReport> }
  // <absolute path to pwsh.exe> -NoProfile -File hyperv-guest/check-io.ps1, request on stdin as JSON {vmName, user, password, checks}
  // the script runs Invoke-Command -VMName with ONE fixed script block that only uses .NET calls ([System.IO.File]::Exists,
  // [System.IO.Directory]::Exists, a bounded [System.IO.File]::Open read) and compares inside the VM. Only findings come back.
  // The password is read from the file at each run, never logged, never put on a command line, never in an event, error or report.
```
A passed check trusts the guest: an AI with admin rights inside the VM could fake it, so it is not tamper-proof.
CLI (B): `room --job ... --checks <file.json> --guest-password-file <file>`; checks file = `{ "<vmId>": [Check, ...] }`, validated
with `validCheck`, at most 8 per VM, unknown VM ids rejected. `--demo` uses the fake checker: Booking form passes, Tests' DONE fails once.

## 8. Workspace file (v0.9)

One JSON file names a room's VMs, tasks, camera labels, automatic checks and limits, so a team keeps it in a repository and
reviews it like code. `albera-runtime room --workspace <file> [--guest-password-file <file>] [--port <n>]`; no other room
option is accepted with it. Example: `examples/albera.workspace.example.json`. Parser: `src/runtime/workspace.mjs` (pure).

```json
{ "version": 1, "name": "booking-site",
  "vms": [ { "vm": "<hyper-v-vm>", "label": "<any script, 1-32>", "task": "<1-2000>", "checks": [Check, ...] } ],
  "limits": { "model": "claude-haiku-5-5", "maxSteps": 40, "maxUsdPerVm": 0.5, "maxUsdTotal": 2, "maxMinutes": 15 } }
```

Rules: unknown fields are refused (a typo or a pasted secret fails loudly); 1-8 VMs, unique; checks as §7; limits within
the same table as the CLI (`LIMIT_RULES`), per-VM not above total; errors are fixed codes, the file content is never printed.

| date+topic | decision | why / rejected | lint |
|---|---|---|---|
| 2026-10-30 workspace-no-secrets | the workspace file never holds secrets or machine paths; the guest password file stays a CLI option | the file is meant to be shared and committed | unknown fields refused (tests) |
| 2026-10-30 workspace-exclusive | `--workspace` takes no other room options | one place to read what a room does. Rejected: CLI overrides on top of the file | tests |
| 2026-10-30 labels-any-script | camera labels may be Japanese (no control characters, 1-32 chars) | labels are shown with textContent only | `isLabel` tests |
