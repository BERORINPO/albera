## PR #9 深掘りレビュー: Runtime Gateway foundation

差分: 12 ファイル・約 1,000 行。本体は `src/runtime/gateway.mjs`（385 行）＋テスト（452 行・24 テスト）。
手元での検証: このブランチで runtime テスト 24/24 通過、arch チェック OK（Linux / Node 24）。

### 良い点

- Observer との分離は arch チェック（2d / 2e / 5a / 5b）で機械的に担保され、既存層から runtime を import できない。
- デフォルト拒否で、リクエスト側の `confirmed: true` では起動できない。生の argv は拒否、argv は固定生成のみ。
- 承認前の argv・環境はスナップショット化され、承認待ち中の呼び出し側の書き換えが spawn に反映されないテストがある。承認コールバックに渡るのは変数名とエンドポイントの host/protocol だけで、秘密値や userinfo・パスは出ない。
- cwd は realpath 化＋許可ルート内チェックで、シンボリックリンク逃げのテストもある。`shell: false`、Windows は `.exe` のみで `.cmd/.bat` 拒否。
- エラーはコードのみで OS の詳細を漏らさない。イベントは 256 件上限で argv・cwd・秘密・出力を含まない。

### P1: そのままマージしてはいけない点

1. Issue #28 承認と起動の間のすり替え（TOCTOU）
   - `start()` の流れが「実行ファイル解決→検証→（非同期の）承認待ち→同じパス文字列で spawn」。承認対象はパスだけで、ファイルのハッシュやハンドルと結びついていない。
   - 承認待ち中に同じパスを差し替えられたら、承認されたつもりの別バイナリが走る。argv・環境はスナップショット化されているのに、実行ファイルだけスナップショット化されていない。
   - 修正方向: 承認タプルにハッシュを含め、spawn 直前に再検証するだけでは不十分で、最終的にはハンドル経由での起動か同等の結び付けが必要。
2. Issue #29 停止確認の言い換え
   - `#requestStop()` がシグナル送信に成功した時点で `treeStopConfirmed = true` にしている。「シグナルを送れた」ことを「木全体が死んだ」と読み替えている。
   - POSIX は `detached: true` のプロセスグループへの kill だが、子が setsid し直せば逃げられる。Windows は `taskkill /T /F` の exit 0 だけで、breakaway やアクセス不能な子孫は証明できない。
   - テストも正常系の親子ヘルパー 1 件だけで、breakaway・PID 再利用・応答ロストの否定系がない。仕様文の「adapter 成功時のみ true」も、実装の「送信成功」とズレている。

### P2: 実用化の前に詰めるべき点

- Claude のフラグへの依存: `--restricted`＋`plan`＋`--print`＋1 ターンで read-only を主張しているが、実際の CLI バージョン確認やフラグの有効性検証はない。`CLAUDE_CONFIG_DIR` など設定系の環境変数も許可リストに入っている。Codex / OpenCode を fail-closed にしている判断自体は正しい。
- sandbox ではない: cwd の許可は作業ディレクトリの制約で、子は現行ユーザー権限で動く。CPU・メモリ・ディスクの quota もなし（時間と同時実行数だけ）。受け入れ基準の RT-05 / RT-09 が VERIFIED になっているのは読み手を誤解させやすい。
- クラッシュ時の孤児: 状態はメモリのみで、Gateway が死んだら子孫は orphan になる。RT-10 は BLOCKED と正しく書いてあるが、解決するまでは永続サービス化は不可。
- 不確定ランが詰まる: `treeStopConfirmed === false` のランは prune 対象外なので、64 件の上限に達すると不確定ランが残り続けて新規起動がずっと capacity エラーになりうる。

### 総評（PR #9）

設計の方向性と隔離・承認の骨格は良い。ただし #9 は #10 以降のスタック全体の土台なので、#28・#29 を残したままマージすると後続全部に穴が引き継がれる。#9 内で修正してからマージするのが筋で、少なくとも「停止は unknown / failed で fail-closed」「承認は実行ファイルの同一性に紐付け」の 2 つは必須条件にすべき。
