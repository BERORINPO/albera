# Desktop "hands" benchmark — 2026-10-29

Which model should drive the mouse and keyboard of an isolated Windows VM? This is a small, informal measurement of Claude models over the API, to help you choose. ALBERA lets you pick other models too; they are not measured here, and nothing here is a recommendation that applies to every task.

## Read this first

- **Small samples.** Each task ran 2–3 times per setup. Treat every number as a rough indication, not a ranking.
- **Claude models only.** All runs used the Anthropic API with the native `computer_toolset_20260801` tool and the full conversation history. No other vendor's model is compared here.
- **Point in time.** Model names and prices are as of 2026-10-29: Claude Haiku 5.5, Sonnet 5.5 and Opus 5.5. The cost column is computed from the token usage each API response reported, at Anthropic API list prices on that date.
- **One machine, one VM.** Windows Server 2025 Desktop Experience (evaluation), 1024×768, 4 GB RAM, 2 vCPU, Hyper-V on Windows 11 Pro, VM disk on a hard disk drive, no network inside the VM.

## How it works

- The host captures the VM screen through Hyper-V (`GetVirtualSystemThumbnailImage`) and drives the VM with the synthetic mouse and keyboard (`Msvm_SyntheticMouse`, `Msvm_Keyboard`). Nothing is installed inside the VM.
- **Pass/fail is checked on the host, inside the guest, through PowerShell Direct** (the file exists with the exact content, the time zone really changed). The model's own "done" is recorded but never counted as success.
- Effort was `low`. The advisor setup adds the `advisor_20260301` tool with Opus 5.5 (at most 3 consultations per request).

## Tasks

| ID | Task |
|---|---|
| t1 | Open Notepad, type a given line, save it to the Desktop as `t1.txt` |
| t2 | In File Explorer, create a folder on the Desktop |
| t3 | In File Explorer, rename `rename-me.txt` to exactly `done.txt` (extensions are hidden by default) |
| c1 | Create `proj\src` and `proj\docs`, move a file into `docs` and rename it |
| c2 | Fill in a local HTML form in Edge, then copy the code it shows into Notepad and save it |
| c3 | Find two values in a 200-line `inventory.txt` and save them in a given format |
| c4 | Change the time zone in Settings / Control Panel |

t1–t3 ran 3 times each, c1–c4 twice each. The advisor setup ran c1–c4 only.

## Results

| Setup | Passed | Said "done" but failed | Avg. time per task | Cost per task |
|---|---|---|---|---|
| Claude Haiku 5.5 | 17/17 | 0 | ~60 s simple, ~176 s complex | ~$0.002–0.006 |
| Claude Sonnet 5.5 | 16/17 | 1 | ~54 s simple, ~142 s complex | ~$0.04–0.09 |
| Haiku 5.5 + Opus 5.5 advisor | 7/7 | 0 | ~199 s complex | ~$0.07 |

Notes:

- Haiku used more actions per task (more trial and error) and was somewhat slower, with the same pass rate at roughly 1/15 of Sonnet's cost on the complex tasks.
- The advisor (Opus 5.5) was consulted once per task, at the start, and accounted for about 90% of that setup's cost without changing the pass rate on these tasks. It may pay off on harder or unfamiliar work.
- The one Sonnet failure renamed the file to `done.txt.txt` (hidden extension) and reported success. Haiku made the same mistake once in the first round, which was excluded (see below). This is why ALBERA verifies results outside the model.
- Excluded runs:
  - The first round of t1/t3 (12 runs; Haiku passed 1/6, Sonnet 3/6) was excluded because the t1 instruction was ambiguous (models typed a trailing "--") and t3 started with a file left over from the previous run. t2 from the same round is included. After fixing both, t1/t3 were run again and those runs are counted.
  - One Haiku + Opus run stopped on a harness bug (a tool result was returned with a field the API rejects). It is not counted.
  - All raw logs, including excluded runs, are in `bench/hands/results/`.
