# ADR 0013: Report provider profile version requirements

## Status

Implemented as static Runtime provider metadata; installed-provider compatibility remains unverified.

Update 2026-10-30 (Issue #35): the advertised floors are now `2.1.310` for both profiles, the only version verified against real repo-supplied hooks/MCP/apiKeyHelper; see `docs/claude-cli-readonly-profile-verification.md`. The 2.1.248 / 2.1.259 figures below are historical.

## Decision

- The read-only Claude profile advertises minimum Claude Code version `2.1.248`, required for `--restricted`.
- The streaming read-only Claude profile advertises minimum version `2.1.259`, required for `--permission-prompts none`.
- Expose requirements through `GET /v1/providers` without probing, launching, or reading local provider configuration.
- Keep the Claude provider status `profile-only` and its runtime validation `synthetic-transport-only` until a separately approved installed-CLI compatibility test passes.
- Continue to reject Codex and OpenCode profiles until their full per-run configuration and side-effect policies can be verified.

## Rationale

Claude Code's current official [CLI reference](https://code.claude.com/docs/en/cli-usage) associates `--restricted` with v2.1.248 or later and `--permission-prompts` with v2.1.259 or later. These are the requirements for the flags already generated by ALBERA. A static capability catalog helps clients communicate prerequisites while retaining the no-probe behavior and avoiding a false claim that an installed version is compatible.

## Verification

`test/runtime-api.test.mjs` verifies the per-profile minimums, unavailable-provider states, fresh projections, and zero provider probes. The catalog test uses only synthetic API state and does not run a provider. Local Windows verification: focused API tests 27/27; `npm test` 513 passed / 3 skipped; `npm run arch` (82 paths, 0 violations); `npm run smoke`; `npm run package:smoke`; `git diff --check`. GitHub Actions run 40499714556 passed all six Windows/macOS/Linux × Node 22/24 jobs, including Windows Runtime storage ACL integration.

## Consequences and limits

- The minimum version fields come from official documentation but do not prove the installed CLI or its effective managed settings behave as documented.
- The catalog does not inspect version strings; compatibility remains a Phase 3 requirement.
- Real-provider checks still require explicit user-visible approval and must disclose outbound data and possible provider charges.
