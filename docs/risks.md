# ALBERA Technical and Security Risks

| ID | Risk | Impact | Mitigation / next action | Status |
|---|---|---|---|---|
| R-01 | A separate local approval host now exists, but it is not integrated with the read-only Observer or a signed/packaged production launcher | A local process that can observe the one-time terminal bootstrap code can access the local host UI; loopback is not OS-user authentication | Gateway defaults to deny. Broker scopes stay server-side; one-time bootstrap is required, UI uses HttpOnly/SameSite cookies plus CSRF/Origin checks, and API bearer tokens never enter browser storage. Keep the independent Runtime command opt-in; add OS identity and packaged-launch review before treating it as a production boundary | OPEN; standalone host prototype only |
| R-02 | Gateway child process runs under the current OS user's privileges; working-directory allowlisting is not a filesystem sandbox | Agent CLI may access/change files outside selected working directory | Runtime UI shows the approved root and exact task text, but that does not constrain filesystem access. Add tested OS sandbox/policy enforcement before broad use; keep provider starts explicitly approved and roots narrowly configured | OPEN |
| R-03 | PATH resolver canonicalizes and checks executable type/permission but does not attest vendor identity or eliminate the final replacement race between post-approval validation and spawn | An unexpected or swapped binary may execute as the current user | Gateway snapshots canonical path and file identity before host approval, then re-resolves and compares device, inode, mode, size, mtime and ctime after approval; changed or missing files are refused before spawn. This detects replacement while approval is pending but cannot close the small OS-level race after the final check or establish vendor identity. Define signature/ownership policy before production provider integration | OPEN; approval-wait replacement regression passes locally; cross-platform CI pending |
| R-04 | Windows `.cmd`/`.bat` launch is unsupported | npm-installed CLI shims may not start on Windows | Reject shims and accept `.exe` only; never enable `shell:true`; design a separately reviewed fixed adapter if needed | MITIGATED; capability deferred |
| R-05 | POSIX process groups and Windows `taskkill /T /F` differ in ownership and descendant cleanup; Windows stop is forceful; Guardian failure, breakaway descendants and PID reuse remain possible | A Gateway crash is covered by a local guardian on the default spawn path, but a guardian failure or process-ID race could still leave or signal the wrong process | Parent-pipe EOF triggers process-tree cleanup; cross-platform helper-process tests passed in Actions run 40465366567. Keep explicit host approval and the disconnected API boundary; use native process handles/Job Objects and stronger platform containment before persistent hosting | OPEN |
| R-06 | Runtime host reuses a journal-specific session ID from a mode-restricted sidecar, but it cannot restore active processes or guarantee the final record across a crash during a write/flush | A hard host/system crash can leave a partial or non-durable tail; startup preserves and refuses an incomplete journal. Unfinished accepted runs become `interrupted`; active recovery remains unavailable | Journal append writes the complete record and synchronously calls `fsync` before returning its Promise. Notification capture starts in the same event turn; periodic polling remains a backstop. Keep active-process recovery unclaimed and add interrupted-run UX, retention/backup policy and Guardian hardening before persistent hosting | OPEN; sync-before-return is unit-tested; crash during write/flush, incomplete-tail recovery and active-process recovery remain unresolved |
| R-07 | Only Claude Code has a generated read-only profile; Codex and OpenCode are refused until external tool/configuration side effects can be excluded | An unverified CLI flag or inherited tool configuration could enable file, shell, MCP or network actions | Generate fixed Claude `--restricted --safe-mode --disallowedTools mcp__*` argv inside the Gateway; reject raw request argv; fail closed for Codex and OpenCode. Organization-managed Claude settings remain trusted host policy. Confirm actual Claude CLI version and behavior before Phase 3; no real provider invocation is claimed | Mitigated at generated profile boundary; real CLI compatibility and managed policy review remain open |
| R-08 | Lifecycle events omit stdout/stderr; journaled events contain only allowlisted state metadata | Limited debugging and no transcript recovery | Continue omitting process output by default; consider bounded provider-aware parsing only after separate threat-model and redaction review | OPEN |
| R-09 | No CPU or memory quota; only active-run count and duration are bounded | A child can consume excessive local resources within its allowed runtime | Evaluate platform-native quotas before public Runtime API and state this limitation in user-facing launch approval | OPEN |
| R-10 | AI CLI account configuration may use paid APIs or transmit prompts externally; the follow-up input path can send additional approved text | Cost and confidentiality exposure | Before approval, the Japanese/English screen warns that approved text may be sent externally and may incur charges; the same warning appears on each start/input approval card. The screen still cannot identify the configured account or estimate cost, and no real provider is invoked by tests. Require per-action approval and keep account/cost discovery open | OPEN; disclosure code-tested only, account/cost discovery unavailable |
| R-11 | Runtime API bearer credentials are local capabilities over unencrypted loopback HTTP; the browser-facing host additionally relies on a one-time terminal bootstrap code and HttpOnly session | Privileged local packet inspection or a process that observes the terminal code can obtain local control; loopback does not authenticate OS users | Keep API bearer token server-side, issue one-use bootstrap, use a 20-minute idle cookie session with an eight-hour absolute cap, enforce Host/Origin/CSRF, no CORS, and never persist tokens. Review TLS/local OS identity or platform-native app authentication before broader deployment | OPEN |
| R-12 | The optional audit/event journal is local JSONL with a single-writer lock, finite capacity, no automatic pruning or backups, and no encryption | Disk loss, corruption, capacity exhaustion, unsafe ownership/permissions, hard links, or full-file replacement can prevent audit/recovery, expose metadata, or modify an unrelated linked file | Never store prompts, paths, argv, tokens, environment or output; any journal write failure permanently disables the API and shuts down the Gateway. Capacity rejection preserves earlier bytes. Windows DACL, POSIX owner/mode, and single-link checks fail closed without repairing existing storage. V2 hashes detect record edits/reordering but are not keyed and cannot detect a recomputed full-file rewrite or an unanchored valid suffix truncation. Keep backup, encryption, independent head anchoring, disk-loss and production retention review open | OPEN; POSIX permission checks passed six-job matrix run 40484508966; hard-link refusal passed run 40485149160; v2 migration/tamper tests and all six Windows/macOS/Linux × Node 22/24 jobs passed run 40498380655; production backup/encryption and independent anchoring remain open |
| R-13 | Synchronous per-record `fsync` can block the Runtime event loop on slow or remote storage | Approval, stop requests, lifecycle capture and browser polling can stall while storage flushes | Journal records are bounded to 2 KiB and the configured journal is capacity-limited. Keep the path explicit, fail closed on errors, and measure flush latency on supported local filesystems before production hosting | OPEN; one-off 100-record Windows temp-path sample with ACL verifier injected: p50 0.638 ms, p95 1.020 ms, max 1.950 ms; actual default temp DACL was correctly refused, so approved-storage latency is still unknown |
