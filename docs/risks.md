# ALBERA Technical and Security Risks

| ID | Risk | Impact | Mitigation / next action | Status |
|---|---|---|---|---|
| R-01 | No approval UI or authenticated Runtime host exists yet | If a future server accepts caller-controlled approval data, untrusted requests could launch or stop processes | Gateway defaults to deny and requires a code-injected host callback bound to the immutable provider/executable/cwd/argv tuple and a redacted provider-environment summary; the exact environment snapshot is reused for spawn. Keep it disconnected until a separately reviewed UI/API exists | MITIGATED; host flow deferred |
| R-02 | Gateway child process runs under the current OS user's privileges; working-directory allowlisting is not a filesystem sandbox | Agent CLI may access/change files outside selected working directory | Do not expose Runtime API until OS sandbox/policy design is approved and tested per platform | OPEN |
| R-03 | PATH resolver canonicalizes and checks executable type/permission but does not attest vendor identity or prevent replacement between validation and spawn | An unexpected or swapped binary may execute as the current user | Host approval includes the canonical path; define signature/ownership and TOCTOU policy before user-facing provider integration | OPEN |
| R-04 | Windows `.cmd`/`.bat` launch is unsupported | npm-installed CLI shims may not start on Windows | Reject shims and accept `.exe` only; never enable `shell:true`; design a separately reviewed fixed adapter if needed | MITIGATED; capability deferred |
| R-05 | POSIX process groups and Windows `taskkill /T /F` differ in ownership and descendant cleanup; Windows stop is forceful; crash/PID reuse remains possible | Windows may lose in-flight child state, and descendants may survive a Gateway crash | Force is disclosed in the host approval request; exit fields are checked before PID signaling; test the process tree on every OS; use platform-native ownership (Windows Job Objects, POSIX service/cgroup policy) before persistent hosting | OPEN |
| R-06 | Gateway restart loses in-memory run/event state and a crash can orphan descendants | Cannot reconnect to active runs or audit prior actions | Keep the module disconnected and do not host as a persistent service; Phase 2 requires supervisor-owned state/recovery design | BLOCKED on supervisor design |
| R-07 | Only Claude Code has a generated read-only profile; Codex and OpenCode are refused until external tool/configuration side effects can be excluded | An unverified CLI flag or inherited tool configuration could enable file, shell, MCP or network actions | Generate fixed Claude `--restricted` argv inside the Gateway; reject raw request argv; fail closed for Codex and OpenCode. Confirm actual Claude CLI version and behavior before Phase 3; no real provider invocation is claimed | MITIGATED for tested Claude profile construction; real CLI compatibility remains open |
| R-08 | Current lifecycle events omit stdout/stderr and are not persisted | Limited debugging/recovery | Keep omission by default; later add bounded, provider-aware parsing and redaction only after threat-model review | OPEN |
| R-09 | No CPU or memory quota; only active-run count and duration are bounded | A child can consume excessive local resources within its allowed runtime | Evaluate platform-native quotas before public Runtime API and state this limitation in user-facing launch approval | OPEN |
| R-10 | AI CLI account configuration may use paid APIs or transmit prompts externally | Cost and confidentiality exposure | Do not launch real providers until approval UI, provider disclosure, cost controls and explicit opt-in are implemented | OPEN |
