## Latest local checkpoint — SQLite snapshot and restore prototype

- `SqliteEnvironmentOperationStore.backupTo()` uses SQLite `VACUUM INTO` for a transactionally consistent snapshot of the live WAL database. It restricts output to the same private storage directory, stages privately, verifies `integrity_check`, `foreign_key_check`, schema version and required tables, and publishes with an exclusive hard link so an existing backup is never overwritten.
- `restoreSqliteEnvironmentStore()` accepts only a verified same-directory snapshot and a new destination. It creates a private `.restore-incomplete` marker before copying. Ordinary opens fail closed while that marker exists; only the restore owner can open the destination, atomically mark interrupted requests UNKNOWN, revoke nonreleased Leases and advance every Computer generation. It removes its exact marker only after commit. Failed or interrupted restore preserves marker and copied bytes for diagnosis and never returns a handle.

## Latest local checkpoint — Broker dispatch fence

- The wire Broker request now accepts the same bounded opaque operation identifiers as the SQLite Journal. Its digest is `sha256:` tagged at the wire boundary while the existing database keeps its hex digest representation.
- `resolveBrokerDispatch()` reloads the operation from SQLite, validates the persisted request schema and recomputes its digest, binds the wire reference to the persisted action digest and generation, checks that the matching Lease remains active and unexpired and the Computer epoch is current, then atomically claims dispatch by changing `REQUESTED` to `UNKNOWN` before returning the journaled operation. A second claim is denied; restart after claim remains `UNKNOWN` and must reconcile. This function does not authenticate the caller and is not an IPC endpoint.

An owner recovery test verifies an interrupted pre-dispatch request becomes `UNKNOWN`; lock tests verify one owner, non-owner shared access, clean release and stale-marker preservation. ## Environment authorization contract checkpoint

The durable Environment coordinator now fails construction if its trusted `authorizeOperation` dependency is absent. The authorizer receives a validated operation, `sha256:` action digest, and purpose (`execute` or `reconcile`). It must return only an exact-shape assertion containing `decision: approved`, approval and approver IDs, the exact operation/idempotency IDs, subject/project/policy version, the matching digest and purpose, and an expiry no more than five minutes ahead. The coordinator normalizes callback failures, rejects mismatch/extra fields/expired grants before it journals an operation, and checks the expiry again after the durable Broker dispatch claim. Reconciliation gets a separate `inspect`-digest approval. At this historical checkpoint grants were transient and never reached the Provider or public operation snapshots. The schema-v4 checkpoint below now persists only their bounded claims and safe audit projection.

This contract does not authenticate the callback, establish that `approverId` is a human, check current policy, durably consume one-time approvals, or bind an OS caller. Those are mandatory responsibilities for the future Control API/approval ledger and authenticated Broker transport. The coordinator remains unwired from Observer and public Runtime routes. The tests use a deterministic Mock authorizer only.

## Guest event storage quota

The SQLite operation store now caps `guest_event_receipts` plus `untrusted_guest` journal rows separately from the shared store capacity. The default quota is 25% of configured `maxRecords`; an explicit `maxGuestRecords` can be supplied only up to 75%, leaving at least one quarter of the shared row budget for Host operations. Accepted Guest events account for two rows (receipt and journal entry); exact deduplicated retries are checked before quota consumption. Exhaustion returns a stable internal `guest_event_capacity` error and rolls back without inserting either row. The existing Guest intake projects unrecognized Store errors to its generic unavailable result, so the internal capacity detail is not exposed to an unauthenticated peer. This is a bounded storage-fairness measure, not a transport authentication control or a global disk/WAL bound; a Guest can still exhaust its permitted share, and retained records are not automatically deleted.
