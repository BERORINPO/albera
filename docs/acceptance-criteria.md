## Phase 2 — Secure Runtime API

| ID | Acceptance criterion | Status | Evidence |
|---|---|---|---|
| API-01 | Runtime API binds only to loopback, uses expiring session-scoped bearer capabilities, validates Host/Origin, and cannot bypass Gateway approval | VERIFIED | `node --test test/runtime-api.test.mjs`: 11/11, including isolation of run listing, lifecycle events, SSE and stop operations across credentials, preservation of lifecycle events emitted while a start request is still resolving, scope separation/revocation, loopback binding, Host/Origin rejection, and the default-deny Gateway boundary. Local Windows Node 24.13.0 `npm test`: 448/448; `npm run arch`: 76 paths / 0 violations; `npm run smoke`: pass. GitHub Actions run 40466146651 passed all six Windows/macOS/Linux × Node 22/24 test and architecture jobs. |
| API-02 | Run/event responses are field-projected; request body, event-stream cursor, client count, lifetime and buffering are bounded | VERIFIED | Local `node --test test/runtime-api.test.mjs`: session-local event IDs stay dense when Gateway events interleave across sessions; the no-journal ring is capped at 256 events/session and 256 session logs, SSE reconnect uses the session cursor, and a transient Gateway event-read failure is recoverable. GitHub Actions run 40470765335 passed tests and architecture checks across Windows/macOS/Linux × Node 22/24. Additional local evidence is recorded in the latest `docs/progress.md` row. |
| API-04 | A scoped, read-only provider catalog reports profile-only and unavailable states without probing or launching a provider | VERIFIED | `GET /v1/providers` is static and reports Claude as profile-only, including official-documentation minimum versions 2.1.248 (`--restricted`) and 2.1.259 (streaming `--permission-prompts none`); it reports the approved version-preflight and synthetic transport validation level without claiming managed-policy or safety certification. Codex/OpenCode remain unavailable. Gateway version checks run only after a separate visible approval; the catalog itself does not probe or launch a provider. Latest tests/CI evidence is recorded in `docs/progress.md`. |
| API-03 | Production host/UI, explicit approval UX, provider input, persistent audit/recovery and crash-safe process ownership are implemented and cross-platform verified | IN_PROGRESS | A separate `albera-runtime` command composes Runtime Gateway, API, broker, redacted JSONL journal and a dedicated loopback approval/control screen; default `albera` Observer startup remains read-only and disconnected. The screen requires a one-time terminal bootstrap code, HttpOnly/SameSite cookie, CSRF+Origin checks and server-side API credentials; prompt/approval content uses DOM text APIs. It supports explicit start/input/stop approvals and allowlisted lifecycle SSE, with Japanese or English copy selected from the browser language; a synthetic-DOM regression verifies Japanese selection. Before approval, the task screen and each start/input approval card disclose possible external text transmission and provider charges; a synthetic DOM test verifies the disclosure on the approval card. Runtime still cannot identify the configured provider account or estimate cost. Each journal append now synchronously writes and calls `fsync` before returning its Promise; tests confirm visibility before return and fail-closed behavior on sync failure. A host/system crash during the write/flush can still leave a non-durable or partial tail, which startup refuses without rewriting; synchronous I/O can stall on slow storage. This change passed all six Windows/macOS/Linux × Node 22/24 jobs in Actions run 40497148500 on `ee12cfb`. A one-off 100-record Windows append sample measured p50 0.638 ms / p95 1.020 ms / max 1.950 ms with ACL verification injected out; the actual default temp DACL was refused, so approved-storage latency remains unverified. A non-secret session-ID sidecar allows journal replay; corrupt or permissive POSIX identity files fail closed and are preserved. Host-level synthetic tests verify completed-run/event replay and unfinished runs projected as `interrupted`, with stale stop denied and no relaunch. Windows DACL and POSIX owner/mode verification fail closed without repairing storage. Journal and lock files with multiple hard links are refused before appending. The journal is append-only with bounded capacity and no automatic pruning. Capacity, POSIX permission, and hard-link behaviors passed cross-platform CI run 40485149160. API-03 remains IN_PROGRESS: manual GUI acceptance, backups/encryption, stronger Guardian/PID-reuse containment, approved-storage latency measurement and production packaging remain incomplete. |
