## Phase 2 — Secure Runtime API

| ID | Acceptance criterion | Status | Evidence |
|---|---|---|---|
| API-01 | Runtime API binds only to loopback, uses expiring session-scoped bearer capabilities, validates Host/Origin, and cannot bypass Gateway approval | VERIFIED | `node --test test/runtime-api.test.mjs`: 11/11, including isolation of run listing, lifecycle events, SSE and stop operations across credentials, preservation of lifecycle events emitted while a start request is still resolving, scope separation/revocation, loopback binding, Host/Origin rejection, and the default-deny Gateway boundary. GitHub Actions run 40466146651 passed all six Windows/macOS/Linux × Node 22/24 test and architecture jobs. |
| API-02 | Run/event responses are field-projected; request body, event-stream cursor, client count, lifetime and buffering are bounded | VERIFIED | Local `node --test test/runtime-api.test.mjs`: session-local event IDs stay dense when Gateway events interleave across sessions; the no-journal ring is capped at 256 events/session and 256 session logs, SSE reconnect uses the session cursor, and a transient Gateway event-read failure is recoverable. GitHub Actions run 40470765335 passed tests and architecture checks across Windows/macOS/Linux × Node 22/24. Additional local evidence is recorded in the latest `docs/progress.md` row. |
| API-04 | A scoped, read-only provider catalog reports profile-only and unavailable states without probing or launching a provider | VERIFIED | Local Windows Node 24.13.0 `node --test test/runtime-api.test.mjs`: 22/22; full `npm test`: 470/470; `npm run arch`: 77 paths / 0 violations; `npm run smoke`: pass. The catalog reports Claude profile construction and synthetic-only input transport validation; it does not claim installed CLI compatibility. Codex and OpenCode remain unavailable. No provider is probed or launched by the catalog. |
| API-03 | Production host/UI, explicit approval UX, provider input, persistent audit/recovery and crash-safe process ownership are implemented and cross-platform verified | IN_PROGRESS | A separate `albera-runtime` command composes Runtime Gateway, API, broker, redacted JSONL journal and a dedicated loopback approval/control screen; default `albera` Observer startup remains read-only and disconnected. The screen requires a one-time terminal bootstrap code, HttpOnly/SameSite cookie, CSRF+Origin checks and server-side API credentials; prompt/approval content uses DOM text APIs. It supports explicit start/input/stop approvals and allowlisted lifecycle SSE. A non-secret session-ID sidecar allows journal replay; corrupt or permissive POSIX identity files fail closed and are preserved. Host-level synthetic tests verify completed-run/event replay and unfinished runs projected as `interrupted`, with stale stop denied and no relaunch. Windows DACL verification runs before journal/sidecar access and fails closed without rewriting ACLs. The journal is append-only with bounded capacity and no automatic pruning. Local Windows verification: full suite 497 passed / 1 skipped; API + journal focused tests 34/34; dedicated DACL integration 7/7; `npm run arch` 82 paths / 0 violations; `npm run smoke` passed. Real-capacity integration confirms a rejected result audit closes the Gateway, makes API health return 503, preserves earlier bytes, and allows safe journal reopen. GitHub Actions run 40482700146 passed all six Windows/macOS/Linux × Node 22/24 jobs for the prior retention-only commit `459d9f7`; CI for the new fail-closed integration regression is pending. No real CLI or GUI was exercised. GUI acceptance, backups/encryption, stronger Guardian/PID-reuse containment and production packaging remain incomplete. |
